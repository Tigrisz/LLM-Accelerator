# 阶段 1A：A1—A3 实施计划

这是 A1—A3 的历史实施范围；不作为整个阶段 1A 的当前实现清单。
后续 A4—A7、S1/S2/S3 已完成；S1 历史基线见 phase1a_baseline.md，当前入口见 platform.md。

依据：本聊天中用户已确认的模块划分、接口契约及阶段 1A 方案。
目标：提供模型无关的接口说明、可验证样本格式和两条独立参考计算路径。
本轮不实现 C 运行时、完整模型、分词器、KV Cache、设备驱动或上板流程。

## 任务与验收

1. A1：定义模块边界、张量/数值规范、模型/会话/后端/平台契约、错误和生命周期。
   提供可执行的基础张量与算子输入检查。测试非法形状、格式、精度、非有限值及整数溢出。
2. A2：定义 fixture-v1。JSON 描述与小端二进制分开；记录来源、逻辑/存储形状、
   偏移、长度和 SHA-256。读取时拒绝篡改、截断、重叠、错尺寸及非零补齐区。
3. A3：实现 Python 标量 FP64/任意精度整数参考，以及独立 NumPy 归约路径。
   覆盖 linear（可选 bias）、add、relu；提供手算/随机/尾部补齐样本和命令行核验。
4. 完整测试、命令行生成/核验、故意破坏输出后的拒绝行为及只读独立审查。

## 本轮具体选择

- Python >=3.10、NumPy >=1.24；标准库 unittest；不安装模型和硬件工具。
- fixture-v1 执行子集仅为 float32/int32、1—4 维连续行优先存储。
  不支持的 dtype/layout/operator 明确拒绝，不默认转成 W4A8。
- FP32 输入按已存储值提升到 FP64 计算，再舍入到 FP32 输出；
  INT32 计算使用无限精度中间值，最终结果越界报错，禁止回绕。
- 小型 FP32 样本逐元素门槛 atol=1e-6、rtol=1e-5，整数精确比较。
  此门槛不是未来所有模型/量化算子的验收标准。
- 单样本二进制最多 16 MiB；单张量最多 1,048,576 个存储元素。
  属于本阶段工具限制，不是最终模型运行时容量。

## 重点检查

- 样本元数据合法但数学维度或引用错误。
- 文件校验通过但 padding、数值或整数结果不合法。
- 广播、自动类型转换或非有限值造成误报通过。
- 两条参考路径共享同一计算算法而无法互相检错。
- 输出覆盖、路径越界、输入失败后仍返回成功。

## 执行方式

先写测试并观察缺失功能失败，再实现和运行完整套件。
在用户明确指定的目录原地工作，不提交、不推送、不修改其他项目。
执行记录见 progress.md，最终结果见 validation_report.md。
