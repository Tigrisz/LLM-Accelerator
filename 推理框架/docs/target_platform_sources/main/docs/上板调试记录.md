采用 GCC 13.2.0、RV32IM/Zicsr/Zifencei/Zba/Zbb、`-O3 -funroll-all-loops -finline-limit=1000 -frename-registers -mtune=sifive-7-series`，performance 种子，2000 次迭代。板级配置为双发射、256 项 BTB、Load 旁路与 early LSU。

时间和每秒成绩以板载 27 MHz **标称**晶振、PLL 旁路为依据，未另用频率计校准。UART 中整数 `Total time (secs)=14`、`Iterations/Sec=142` 有截断，不能替代完整周期换算。此处为实板测试记录，未经 EEMBC 认证。资源边界为整个 SoC，包含 TCM、UART 和 GPIO。

原始 UART、下载校验日志、仿真对照、时序、资源和 manifest 已归档至 `docs/results/board-27mhz/`。CoreMark 位流及工程保存在 `build/board27-coremark/`，当前 FPGA 中最后下载的是这个镜像。

本次采用易失的 FPGA 配置 RAM 下载。尚未执行外部 Flash 固化、断电重启测试、validation 种子长测或高频 PLL 稳定性测试。

## 本次修复

1. Config 无法启动：PDS `bin/ftd2xx.dll` 是依赖缺失 CH347 库的替代版本，返回 `0xC0000135`。备份后恢复 PDS 自带的 amd64 FTDI 3.02.09 库，Config 和 JTAG 扫描恢复。
2. 旧位流早于最新板级源码与布局布线结果，重新生成当前版本。
3. `prepare_board.ps1` 的裸 `save_project` 在命令行流程中报 `Flow-4055`，阻断生成位流，现已移除。
4. PDS 会预解析 Tcl 的文件读取，不能在全新目录的同一 Tcl 中先构建、再读取尚未生成的时序报告。现在由 PowerShell 检查新时序报告，再在独立 PDS 调用中显式选择器件并读取本次布局布线数据库生成位流。
5. 新增 `program_board.ps1` 和 `program_board.tcl`，串口在下载前打开，自动核对构建哈希、执行 JTAG 编程、捕获预期 UART 文本，再执行配置校验。
6. 实测发现：下载后立即 `cfg_verify` 时 smoke 可完成，但 CoreMark 在 90 秒内无 UART 输出；同一镜像仅下载时能完成。调整为 **下载 → 等待完整 UART 结果 → 配置校验** 后，CoreMark 再次以相同周期和 CRC 完成，后续校验也通过。长程序运行时避免执行配置回读/校验。

## 复现

从 `D:\FPGA\RiscV` 的 PowerShell 执行：

```powershell
# 基础启动镜像
.\scripts\prepare_board.ps1 -ClockMHz 27 -Firmware build\smoke.hex -Build -Bitstream
.\scripts\program_board.ps1 -Port COM12 -Output build\board-uart.log
```

CoreMark 固件与完整镜像的复现：

```powershell
wsl -d Ubuntu-24.04 -- bash -lc 'cd /mnt/d/FPGA/RiscV && make coremark-build ITERATIONS=2000 CPU_HZ=27000000 MARCH=rv32im_zicsr_zifencei_zba_zbb EXTRA_CFLAGS="-funroll-all-loops -finline-limit=1000 -frename-registers -mtune=sifive-7-series" && cp build/coremark.hex build/board-coremark-performance.hex'
.\scripts\prepare_board.ps1 -ClockMHz 27 -Firmware build\board-coremark-performance.hex -OutputDirectory build\board27-coremark -Build -Bitstream
.\scripts\program_board.ps1 -Port COM12 -Profile build\board27-coremark -Output build\board-coremark.uart.log -Expected 'MEASURED_CYCLES_HEX=[0-9a-fA-F]{16}\r?\n'
python scripts\analyze_board_coremark.py build\board-coremark.uart.log --clock-hz 27000000 --luts 6634
```

`program_board.ps1` 的预期文本只判断采集完成；CoreMark 算法和持续时间校验由 `analyze_board_coremark.py` 执行。

串口号由 Windows 分配；换 USB 插口后以设备管理器中的 CP210x 端口为准。FTDI COM10/COM11 属于下载器，不是底板 UART。

根目录 `RiscV.pds` 使用不含引脚分配的 `fpga/timing.fdc`，用于时序探索。实板应打开 `build/board27/qinglong_board.pds` 或使用脚本生成的其他完整板级 profile。
