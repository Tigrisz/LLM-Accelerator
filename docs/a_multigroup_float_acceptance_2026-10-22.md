# A：K256/K384板端结果与Qwen浮点评估验收

## 验收结论

B 分支 `codex/b-multigroup-uart-cases` 的 `44544a5`、`1a58b91` 已整合到 A 独立分支。
交付中的“未提交”是历史打包状态，不能据此遗漏后续已推送的实现。
验收读取原始证据，不覆盖归档，不重新宣称 A 操作了硬件或重放了模型。

| 用例 | 输入 | 每帧条数/字节 | 复位采集 | A离线验收 |
|---|---|---|---|---|
| N3/K256 | A合成signed INT4/INT8 | 6 / 57 | 3次 | 18条标签、顺序、值均匹配 |
| N3/K384 | A合成signed INT4/INT8 | 9 / 81 | 3次 | 27条标签、顺序、值均匹配 |

多组验收核对A原ZIP与全部fixture字节，再由独立nibble解包和Python整数点积重算；
校验NPY/MEM、三次原始帧、B统一JSON及位流与下载记录。使用 `struct` 直接读取帧，
不依赖B解码器的已有passed字段，并调用A统一CLI检查标签/顺序/数量。
两套用例各自三帧字节完全相同，六次共45条实板记录通过。
硬件来源及KEY0/LED确认依据B记录，UART v1未携带LED或位流ID。
K384首次SCBV告警的诊断日志保留，验收关联的是修复后最终位流。

## 浮点参考与误差

固定revision：`989aa7980e4cf806f80c7fef2b1adb7bc71aa306`。
layer0 o_proj，N16，有效1536/物理2048列，同一prompt、最后token，无bias。
参考是BF16加载值在量化前转FP32保存，再以FP64计算；不是原生FP32模型重推理。
A复核5份重新量化载荷和3份ROM逐字节一致，旧Qwen三次UART也全部匹配。
A另用逐元素 `math.fsum` 重算浮点点积和误差指标，与B评估吻合。

| 指标 | A独立复算（约值） |
|---|---:|
| 最大绝对误差 | 0.07159525168 |
| MAE | 0.02476722980 |
| RMSE | 0.03205080544 |
| 相对L2 | 9.7096696% |
| 最大逐行相对误差 | 63.7885265% |
| 余弦相似度 | 0.9954904542 |

最大绝对误差行是row9，最大相对误差行是row15；完整参考值、实际值及逐行误差写入报告。
相对误差分母为abs(reference)，仅对abs(reference)>1e-12的行计算，本次无排除行。
`status=pass`表示数据对应与计算验证成功，`accuracy_accepted=false`表示尚未约定精度验收阈值。
不能将高余弦相似度替代逐行误差检查，也不能从16行/单token推广完整模型质量。
A没有加载数GB checkpoint，模型来源复现记录由B提供，A核验了对应元数据及载荷。

## 重现与报告

在仓库根目录、Python 3.10+和NumPy环境运行：

```bash
python scripts/accept_multigroup_float.py
python scripts/run_regression.py
```

第一条只做离线文件/数值验收，无需开发板、PDS或Torch；每次使用新的attempt目录。
第二条保留双方已有全部阶段，并增加A板端/浮点验收阶段。
目录 `build/reports/a_board_float_acceptance/summary.json` 指向最近一次结果；
同目录attempt子目录下保存六份统一capture、比较报告、重新量化数据和独立浮点指标。
`float/a_independent_metrics.json`含16行明细与精度边界；原始证据均保持不变。

两份交付ZIP分别核对120和91个成员哈希。完整回归另外记录提交号、源码哈希和工具版本；
CI现有artifact上传规则保留整个reports目录。
