# 16 路存储链路适配与 B 交接

## 范围

本次基于 `4115376`（PR #2）增加 `paired_lane_adapter`。
存储侧仍为每拍 128 位权重（32 个 INT4）和 256 位激活（32 个 INT8）。
`LANES=16` 时按低半、高半顺序发送至计算核心；`LANES=32` 时直通。
分组仍为 128 元素，输出仍为带 row/group 标签的 INT32 部分和。
不需要 B 重新打包权重、修改激活缓存或改变 Python golden。

## 接入方式和约束

放在 `paired_input_stream` 与 `gemv_core` 之间，两个模块的 `LANES` 保持一致。
可参考 `tests/tb_b_integration.sv` 的接线；该文件是仿真夹具，不能直接视为板端顶层。

- 低半拍输出权重 `[63:0]`、激活 `[127:0]`；高半拍输出剩余高位。
- `group_first` 只在低半拍有效，`group_last` 只在高半拍有效。
- 两个半拍保持同一 row/group 标签。
- 适配器只保存半拍位置，不缓存数据。16 路模式仅在高半拍被接收时拉高上游 ready。
  因而上游必须在 valid 且未握手期间持续保持 valid、权重、激活和全部标签稳定。
- 每个存储拍需要两次下游握手；无停顿时每周期输出一个 16 元素拍。
- 同一任务配置保持不变；复位必须覆盖上游、适配器、计算核心，复位后重新发起任务。
  不支持只复位适配器后从任务中途继续。
- 读取完成不等于计算结果已被接收，完成判定仍需等待最后一个输出握手。

## 复现命令

在仓库根目录，使用含 NumPy 的 Python 环境：

```bash
make test-adapter PYTHON=python
make test-integration16 PYTHON=python
make test-integration PYTHON=python
python scripts/run_regression.py
```

默认 `make test-integration` 仍为 32 路。16 路二进制位于
`build/integration16/Vtb_b_integration`，与 32 路构建目录分离。
完整回归将自动执行两种并行度，并在失败时尝试生成 VCD。

## 验证覆盖

- 独立适配器：20 个种子、5120 个存储拍，逐拍核对两半数据、标记、标签及握手次数。
- 两个半拍各保持 513 周期背压；两个半拍位置分别复位；257 周期空闲间隔。
- 16/32 路分别使用 4 组 B 原始数据、100 组随机数据、K=2048/6144/8192 三组长向量。
- 每例连续两次任务、随机输出暂停、最终结果背压、传输计数和 B golden 比对。
- 每个组内拍位置复位、待输出复位、缓存容量与错误地址/配置检查。

机器执行结果以 `build/reports/summary.json` 和各阶段日志为准。

## B 当前需要做什么

首次上板可以继续使用 32 路，不必等待 16 路综合或修改存储格式。
如需切换 16 路，加入适配器并遵守上述 ready/valid 与复位约束。
后续请同步板卡/FPGA 型号、目标频率、板端顶层和实际切片，A 再配合综合与上板验算。

当前仍是合成数据仿真验证；尚无真实模型切片、FPGA 资源/时序或板端结果。
日志中的周期数受模拟存储延迟和停顿影响，不代表实测 DDR 带宽或模型 token/s。
