# 候选接入能力差距分析（S6 v1）

当前运行时0.6.0/native ABI2；T4指定链、T5/T6单节点样本、T7原FP32/INT32四节点链RV32仿真分别有范围限定，实际结果见各期验证报告，不能将受测链/样本或PC支持集升级为任意目标模型验证。没有具体候选，以下是条件差距目录，不是对某模型的兼容结论。
优先级由实际候选关键路径、质量/内存/性能需求决定；不预设LLM、KV或W4A8。

## 条件转换不等于已经接入

- 固定常量权重转置/重排：若源语义和目标[N,K]明确，可在离线阶段转换；须保存前后哈希、
  轴映射、golden和转换峰值。运行时transpose算子仍未实现。
- batch展开为多个静态profile/独立向量链：只有图确实独立且输入/输出映射得到证明时可提出；
  须重算节点/张量上限、内存与吞吐，没有自动展开器。
- 融合算子拆分：必须先证明数学/数值/量化舍入语义；拆分产生的新算子也需已实现，不能只改名称。
- 反量化到FP32：可以作为待选择的PC试验方案，当前没有通用量化导入器；
  转换不再保留原量化计算路径/存储成本，需另算内存/精度，不能据此标记原编码supported。
- 静态profile特化：每个实际shape都要包/规划/验证，不表示当前引擎支持符号维或动态重新规划。

## 明确不做的隐式替换

不把INT8/packed位流reinterpret为INT32；不把缺失量化参数默认为无量化；
不静默广播/flatten/转置/降精度；不在后端执行失败后改用参考Python重跑；
不把matmul/Gemm/fully_connected等名称直接映射为linear而省略属性与shape核对。
任何转换若没有实现或验证证据，记录为pending_validation，不进入supported或conditional_conversion清单。
只有显式转换方案、数值证据与实际执行路径齐备时才记录conditional_conversion，仍需明确转换后的执行语义与资源成本。

## 模型未确定时下一步

现在可以使用模板收集候选的真实导出清单，并准备目标内存图/驱动接口和独立评测数据；
按OP/DT/Q/LAY/MEM需求ID汇总GAP，先处理关键路径阻断项。
待材料齐备后，为每项扩展单独制定实现与数值/资源/目标机验收方案。
本轮整理不会自动引入新算子、量化库、外部模型下载或硬件配置。
