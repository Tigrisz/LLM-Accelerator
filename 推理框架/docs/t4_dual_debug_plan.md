## 调查记录

- 初始事实：默认异常点是CRC读取循环的lbu，不能据此认定CRC或ABI为根因；先比较程序顺序的retire PC/指令/写回数据。
- 首次架构差异为退休序号1522、PC0x3f18的andi：原Verilator单发射写0x14，双发射写0xff94；前一sub同周期与它退休。队列记录cycle1553中sub元数据0x47、andi元数据0，pair_swapped=1，造成同对RAW/WAW漏检。
- 关键反证：相同原始RTL/原完整ELF，Icarus双发射通过，445747周期，正常/零输出正确；56字节汇编例也在Icarus两配置通过，而Verilator原双发射退出3。不能将它归因于已证实的CPU硬件逻辑缺陷。
- 已检查原Verilator5.032生成C++：元数据追加赋值在压缩赋值之前应用，压缩覆盖追加；对应PC/指令字段仍以追加为后写，造成payload/meta错位。简单静态/动态FIFO归约未复现同一编译排序问题，仅作为对照；真正最小复现是完整CPU加56字节ELF。
